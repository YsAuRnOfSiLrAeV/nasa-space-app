# forestrecovery

Стадія відновлення лісу після пожежі за сигналами NISAR, Sentinel-1 і NDVI.
Тільки Python + numpy (pandas за бажанням). Усе вже навчене, нічого додатково підключати не треба.

## Підключення (2 способи)

1. Скопіювати папку `forestrecovery/` у свій проєкт поряд з кодом. Готово.
2. Або з кореня проєкту: `pip install -e .`

## Використання

### Таблиця: один рядок = один піксель

```python
from forestrecovery import predict_table

out = predict_table(df)   # df з колонками: nisar_HV, nisar_HH, s1_VH, s1_VV, NDVI
out[["stage_name", "p_forest_gt5"]]
```

### Растри numpy будь-якої форми

```python
from forestrecovery import predict_arrays

r = predict_arrays(nisar_HV=hv, nisar_HH=hh, s1_VH=vh, s1_VV=vv, NDVI=ndvi)  # 2D масиви
r["stage"]          # int8: 0, 1, 2 або -1 (невалідний піксель)
r["p_forest_gt5"]   # float32 0..1, NaN для невалідних
```

## Що подавати на вхід

| Колонка | Що це | Одиниці | Допустимий діапазон |
| --- | --- | --- | --- |
| `nisar_HV` | NISAR, крос-поляризація (найважливіший) | **dB** | -26.8 ... -4.6 |
| `nisar_HH` | NISAR, пряма поляризація | **dB** | -25.3 ... 2.8 |
| `s1_VH` | Sentinel-1, крос-поляризація | **dB** | -30.8 ... -8.5 |
| `s1_VV` | Sentinel-1, пряма поляризація | **dB** | -21.4 ... -1.9 |
| `NDVI` | Зелень з Sentinel-2 | 0..1 | 0.2 ... 1.0 |

Різниці `HV-HH` та `VH-VV` рахувати **не треба**, бібліотека робить це сама.
Інші колонки ігноруються. Якщо дані в лінійних одиницях (сирий GCOV), перетворіть їх: `from forestrecovery import to_db`
(середнє беріть у лінійних одиницях, а в dB переводьте після).

## Що повертається

| Поле | Що це |
| --- | --- |
| `valid` | `True`, якщо вхід у допустимих межах. Невалідні (NaN, вода, поза діапазоном, NDVI < 0.2) не оцінюються |
| `stage` | 0 = до 5 м, 1 = 5-10 м, 2 = понад 10 м, -1 = невалідний |
| `stage_name` | назва стадії текстом (лише у `predict_table`) |
| `p_0_5`, `p_5_10`, `p_gt10` | ймовірності трьох класів, у сумі 1 |
| **`p_forest_gt5`** | ймовірність, що висота понад 5 м. **Найнадійніше число, його варто показувати в першу чергу** |

Середній клас (5-10 м) модель розпізнає слабко. Для демо показуйте `p_forest_gt5` або карту «до 5 м / понад 5 м».

## Колір для карти (пропозиція)

`stage` 0 червоний, 1 жовтий, 2 зелений; невалідні пікселі прозорі. Або градієнт за `p_forest_gt5` від червоного (0) до зеленого (1).

## Регіони: яка модель для якого місця і наскільки їй вірити

Світ розбито на **регіони за кліматом і типом лісу, у кожному три країни, без змішування між регіонами**. Кожен регіон має власну модель,
навчену лише на його країнах:

| Регіон (`region`) | Клімат | Країни |
| --- | --- | --- |
| `continental` (за замовчуванням) | помірно-континентальний (Dfb) | Канада, Україна, США |
| `mediterranean` | середземноморський | Греція, Туреччина, Іспанія |
| `savanna` | тропічна савана | Замбія, Танзанія, Бразилія (Серрадо), лише «структура зараз» |
| `monsoon` | мусонні сухі ліси | Індія, Таїланд, Камбоджа |

Які регіони й країни вже готові, і **актуальні числа надійності** з інтервалами: [REGIONS.md](REGIONS.md) (його генерує `scripts/build_regions.py`).
Перевірка чесна: «одна країна проти решти регіону» (модель навчили на інших країнах регіону й перевірили на цій). Надійність: good ≥ 0,70 (AUC «ліс >5 м»), moderate 0,62-0,70, low < 0,62. Інтервали в 35-130 пожеж на країну широкі: дрібні різниці нічого не доводять.

**Модель вважається перевіреною лише там, де ми дивились.** «Слід» це комірки 0,5° навколо наших точок разом із сусідніми (≈ 50-100 км). Поза слідом (Лондон, Амазонія, Сахара, навіть сусідня країна регіону, якої ми не брали) це `out_of_domain`, а не припущення.

```python
from forestrecovery import predict_arrays, predict_table, region_for, route, footprint_geojson, list_regions

region_for(31.43, 36.95)    # Манавгат: {'region': 'mediterranean', 'country': 'turkey', 'reliability': 'moderate', 'message': '...AUC 0.64...'}
region_for(-60, -3)         # Амазонія: {'in_domain': False, 'model': None, 'reliability': 'out_of_domain'}

predict_arrays(..., region="mediterranean")                     # явно (приймає й країну: region="greece")
predict_arrays(..., region="auto", lon=31.43, lat=36.95)        # модель за координатами; поза слідом OutOfDomainError
predict_arrays(..., region="auto", lon=lon, lat=lat, on_out_of_domain="nan")   # поза слідом пікселі невалідні
predict_table(df, region="auto")                                # координати з колонок longitude / latitude; додається колонка model
footprint_geojson()                                             # де ми дивились: комірки сліду як GeoJSON для шару на карті
```

- `region_for()` повертає також `validated` (запис про цю країну) і `message`: готовий підпис для інтерфейсу.
- За замовчуванням `region="continental"` (стара назва `boreal` працює як псевдонім). Регіон без моделі (`savanna`, `monsoon`, поки немає даних) дає `ValueError` із поясненням.
- `DemoFire.predict()` вибирає модель сам за координатами пожежі.

**Крива росту (`Growth`) підтверджена лише для Канади.** У регіоні `continental` вона не переноситься на США й Україну: вік пояснює відновлення тільки в Канаді (Спірмен +0,72), і тільки для віку 19-35 років (до ≈ 20 років висота стоїть на ≈ 0,42 від довоєнної, далі росте до ≈ 0,8 до 35 років: довга пауза і потім ріст, не експонента). У США (вік 4-18) і Україні (3-17) залежності від віку немає. `Growth.for_location()` для цих країн кидає `ValueError` з поясненням (`growth_info()["evidence"]`); `allow_unvalidated=True` бере канадську криву з попередженням. Для `mediterranean` відновлення не залежить від віку (143 пожежі), для `savanna` пожежі щорічні, для `monsoon` даних немає. Можна задати `A` і `tau` вручну.

Оновити моделі після нових даних у `data/regions/nisar_<країна>.csv`: `PYTHONPATH=.:scripts python scripts/build_regions.py`.

## Вибір полігона: правило 80% і кольорові регіони

Користувач вибирає пожежу лише в територіях, де модель перевірена. Інтерфейс малює їх різними кольорами (`territory_geojson()`), а після вибору полігона викликає `assess_territory(polygon)`:

```python
from forestrecovery import assess_territory, territory_geojson

territory_geojson()                       # шар для карти: де ми перевіряли, колір на регіон (properties: region, country, color, reliability)
a = assess_territory(polygon_geojson)     # GeoJSON Polygon / MultiPolygon / Feature / FeatureCollection або список [[lon, lat], ...]
a["status"]                               # "inside" (>= 80% полігона в одному регіоні) або "outside"
```

- **`inside`:** `a["region"]`, `a["country"]`, `a["fraction"]`, `a["reliability"]` (+ `a["validated"]` з AUC), `a["model"]`, `a["show"] == "state"` (показуємо оцінку стану моделлю регіону). `a["forecast"]` каже, чи є підтверджений прогноз (`growth_curve` для Канади, `severity_scenario` для Середземномор'я, інакше `available=False` з причиною); `a["ask_forecast"]` це чи питати «Хочете прогноз для цієї ділянки?». `a["message"]` готовий текст (`lang="uk"` або `"en"`).
- **`outside`** (менше 80% в одному регіоні): `a["show"] == "imagery_only"`, тобто лише знімки на зараз, `a["message"]`: «Прогноз на цю дату не можемо. Переоберіть територію так, щоб щонайменше 80% полігона лежало всередині підсвіченого регіону…». Поріг: `min_inside=0.8`.
- `coverage(polygon)` показує частки по регіонах; полігон береться вибіркою точок усередині (дірки в полігоні враховуються).

Територія регіону це **екорегіони (тип лісу), де лежать наші навчальні точки** (`scripts/gee_ecoregions.js`, поділ RESOLVE 2017) разом із комірками 0,5° навколо точок, збирається `scripts/build_territory.py` у швидку сітку 0,05° (`territory_grid.npz`, десятки КБ). **Росія не покривається** (немає наших даних, GEDI туди не сягає); інші сусідні країни (Білорусь, Польща тощо) входять, лише де вони реально потрапляють у регіон, і в результаті мають `extrapolated = True` (країна не входила до навчання, тип лісу той самий; надійність береться як у найгіршої перевіреної країни регіону). Межі країн грубі (Natural Earth 110m): біля самого кордону можлива похибка в кілька км.

## Сценарій «що якби пожежа була сильнішою» для Середземномор'я

Для Греції, Туреччини й Іспанії **траєкторії висоти за роками немає**: висота лісу не залежить від віку пожежі (3-20 років; перевірено трьома способами, з силою пожежі, кліматом і ґрунтом теж). Що дані підтверджують:
- **рівень висоти** (частка висоти сусіднього незгорілого лісу) залежить від **сили пожежі**: слабка ≈ 0,8, сильна ≈ 0,6 (нахил −0,34, 95% інтервал [−0,46; −0,20], 139 пожеж);
- **зелень** (літній NDVI відносно NDVI до пожежі, реальні ряди MODIS через 1, 3, 5 років) відновлюється з часом: за 5 років до 93% після слабкої пожежі і до 80% після сильної.

Разом це «оптика бреше» в даних: зелень повертається за 5-8 років, а висота лишається нижчою за довоєнний ліс.

```python
from forestrecovery import Scenario, severity_from_loss

sc = Scenario("mediterranean", country="spain")        # country: greece | turkey | spain | None (середнє); або Scenario.for_location(lon, lat)
sc.severity_levels()                                    # {'weak': 0.12, 'medium': 0.47, 'strong': 0.78}
sc.structure_level(0.8)                                 # {'mean', 'lo', 'hi' (окрема пожежа, 90%), 'mean_lo', 'mean_hi' (середнє)}
sc.greenness(0.8, years=range(1, 16))                   # зелень за роками (дані до 5 років, далі екстраполяція)
sc.compare(0.8)                                         # зелень + рівень висоти + розрив між ними: готово для графіка двох ліній
sc.hindcast(fire_year=2000, severity=0.8, until=2026)   # пожежа 2000 року до 2026: рік за роком (поле observed: 1, 3, 5 років справжні)
sc.what_if(fire_year=2000)                              # слабка / середня / сильна поруч
severity_from_loss(loss_year_array, fire_year)          # сила пожежі з Hansen lossyear (0..1)
```

Сила пожежі = частка території, де Hansen фіксує втрату крон у рік пожежі або наступний (0 слабка ... 1 сильна). **Застереження:** зв'язок кореляційний, не причинний; у Греції сила пожежі нічого не пояснює (власний нахил ≈ 0), у Туреччині й Іспанії пояснює; зелень після 5 років екстрапольована з трьох точок. `info()` повертає всі параметри й застереження для підпису. Для `continental` сценарію немає: там прогноз за роками дає `Growth`. Параметри перераховує `scripts/build_scenario.py`.

## Ріст лісу в часі (те саме, що в 3D-демо)

Модель 2 дає криву відновлення за віком пожежі: `recovery(age) = A·(1 − exp(−age/τ))`, де recovery це висота лісу, поділена на висоту лісу до пожежі. Крива підігнана на 49 пожежах Канади: A = 1, τ ≈ 25 років, **80% досягається приблизно за 41 рік**.
Сьогоднішній стан кожного пікселя береться з `predict_arrays`, далі піксель росте до 100% зі своєю швидкістю.

```python
from forestrecovery import predict_arrays, Growth

pred = predict_arrays(nisar_HV=hv, nisar_HH=hh, s1_VH=vh, s1_VV=vv, NDVI=ndvi)   # 2D растри
g = Growth()
sim = g.simulate(pred, fire_year=1995, ref_height_m=9.7, burned=burn_mask)       # now_year=2026 за замовчуванням

sim.recovery_at(2050)     # 2D float32, 0..1: частка висоти лісу до пожежі в 2050 р.
sim.height_at(2050)       # метри
sim.stage_at(2050)        # стадія 0/1/2 за висотою (-1 = невалідний)
sim.stats_at(2050)        # {'mean_recovery', 'share_target', 'model_recovery', ...}
sim.year_reached(0.8)     # 2D: рік, коли піксель досягне 80% (карта «коли відросте»)
```

Що треба передати: `fire_year`, `ref_height_m` (висота сусіднього незгорілого лісу, м; у нас це медіана GEDI rh98) і `burned` (bool-маска згарища тієї ж форми, без неї все вважається згорілим). Поза згарищем і до року пожежі ліс завжди на 100%.

| Метод | Що робить |
| --- | --- |
| `Growth().recovery(age)` | крива рівня пожежі (число або масив) |
| `Growth().years_to(0.8)` | скільки років від пожежі до 80% (≈ 40,6) |
| `Growth().years_left(age_now, 0.8)` | скільки років лишилось |
| `Growth().curve(max_age)` | `(ages, recovery)` для графіка |
| `Growth().simulate(pred, ...)` | піксельна симуляція (`GrowthSimulation`) |
| `Growth().simulate_from_signals(hv, hh, vh, vv, ndvi, ...)` | `predict_arrays` + `simulate` за один виклик |
| `Growth().add_forecast(df, fire_year=..., ref_height_m=..., years=(2040, 2060))` | те саме для таблиці `predict_table`: колонки `height_now_m`, `recovery_now`, `year_reached_80`, `recovery_<рік>` |
| `sim.timeline(years)` / `sim.frames(years)` | список зведень / генератор кадрів для анімації |
| `expected_height(pred)`, `stage_from_height(h)` | очікувана висота з ймовірностей, стадія за висотою |
| `growth_info()` | версія кривої, A, τ, на скількох пожежах навчена, чи пройшла перевірку |

Кожен піксель підганяється так, щоб його крива проходила через сьогоднішній стан, а середнє по згарищу збігалось із кривою моделі 2 для цього віку (`calibrate=True`).
Це ілюстрація за стабільних умов: без нових пожеж, зміни клімату й випадковості. Крива навчена на віці 9-35 років, поза ним це екстраполяція. Статистика на рівні пікселів трохи шумніша, ніж на блоках 360 м у 3D-сцені (шум радара).

## Готовий 3D-глобус з повзунком часу

Один HTML-файл (Three.js підтягується з cdnjs, потрібен інтернет): глобус із пожежами, політ до пожежі, компас і масштаб, повзунок року, перемикач «як бачить оптика», стовпчики GEDI, UK/EN.
Повзунок рухає лише вибрану пожежу, а коли нічого не вибрано, усі разом.

```python
export_globe([scene1, scene2], "growth.html")                               # відкрити в браузері
export_globe([scene1], "growth.html", standalone=False)                     # без doctype, для публікації як артефакт
```

- `scene_data([scene, ...])` повертає dict (JSON) для власного фронтенду: клітинки 360 м зі станом, кольором, ознакою згарища і параметри кривої.
- `locate(x, y, crs)` рахує `(lon, lat, rot_deg)` центру растра в проєкції (потрібен `pyproj`).
- `load_demo_rasters(demo_tif, nisar_tif)` читає пару растрів з GEE і Colab (потрібен `rasterio`).
- Повний приклад «растри → модель → ріст → глобус»: `scripts/build_world_growth.py`.
