## Historical review: e352076

Authority: `backend/pipeline/export.py` (`CELL_LAYERS`, `RESULT_SECTIONS`, `index_entry`, `write_fire`), `grid.py`, `contract.py`, `fire_stats.py`, `gee/layers.py`, `gee/gedi.py`, and `tests/test_export.py` at commit `e352076`. The exporter is a Python dictionary writer, not a complete nested JSON schema. The runner and model integration are stubs, so there is no completed production result assembly to treat as an additional schema. Requirements below distinguish actual writer guarantees from frontend validation.

## index.json

An array; `index_entry` always writes every key below. Existing index entries are replaced by fire id.

| Keys                                     | Writer behavior / frontend validation                                                                                                                                                   |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| id, name, year, area_ha                  | Copied from required fire dictionary keys. Frontend requires nonempty id, name.en, name.uk, positive integer year, positive area or null. Writer does not validate these nested values. |
| summer                                   | Required satellite_images.summer; frontend positive integer.                                                                                                                            |
| center_lonlat                            | Polygon centroid rounded to four decimals, [longitude, latitude]. Frontend validates coordinate ranges. A null perimeter cannot produce an index entry.                                 |
| recovery_today_avg, area_recovered_80pct | `.get` from model_result or empty object, so missing inputs become null. Frontend accepts null, nonnegative recovery, and area fractions in 0..1.                                       |
| year_80pct                               | `.get` from growth_forecast or empty object, missing becomes null. Frontend accepts null or positive integer.                                                                           |
| result                                   | Always `<fire_id>/result.json`; frontend validates safe relative paths.                                                                                                                 |

## result.json

`write_fire` requires these nine top-level sections to be present: fire, satellite_images, map_grid, neighbour_forest, model_result, growth_forecast, comparison, lidar_points, warnings. It adds schema_version=1 and files. It checks grid array lengths, but does not validate nested scientific fields. Its comments permit inapplicable sections to be null; frontend supports null neighbour_forest, model_result, growth_forecast and comparison. Required fire/grid/summer/point-list/warning-list structures cannot be null in the frontend.

## cells.json

The writer can return `{}`. Groups and individual arrays are all optional. A supplied array must have exactly rows × columns entries, flattened row-major. Missing pixel values are JSON null. Entire null arrays/groups are not emitted and are rejected. Missing arrays are normalized to independent full-length null arrays at the loader boundary; the renderer retains its full-array contract. Explicit null entries and explicit zero measurements are preserved.

| Group  | Allowed layers / units                                                                                                                                                                                      |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| model  | stage: 0/1/2 or null; p_forest_gt5: percent 0..100 or null; recovery: nonnegative percent or null.                                                                                                          |
| map    | zone: 1=burned area, 0=reference forest, null=excluded; confidence: code 0/1/2 or null accepted for legacy compatibility, but meanings are not defined in this backend; reburn_year: positive year or null. |
| optics | ndvi: -100..100 or null (backend multiplies NDVI by 100).                                                                                                                                                   |

The writer rounds arrays to integers. Existing frontend numeric range validators are retained, including acceptance of finite fractional values within range for legacy data. Extra cell layer names cannot be generated by the writer. Zone codes are never used as reliability classifications. Undefined confidence codes no longer mask supplied predictions or claim geographic applicability. Geographic applicability polygons remain a separate unavailable dataset; no geometry is derived from map.zone or map.confidence.

## Warnings and processing

`fire_stats.warnings` emits LOW_NISAR_COVERAGE when less than 0.8 of burn-zone cells contain NISAR data. Missing covariates emit DEFAULT_DNBR, DEFAULT_NBR_PRE, DEFAULT_ELEV, DEFAULT_SLOPE, DEFAULT_SOIL_CLAY, DEFAULT_SOIL_SAND, DEFAULT_SOIL_ORG_C and DEFAULT_DIST_EDGE_M. The function accepts any covariate mapping, so unknown DEFAULT codes also remain possible; only the documented standard list gets specific messages. Its docstring specifies Canada-mean defaults. Existing legacy fixture warnings remain supported without treating them as newly implemented backend behavior.

Only GET /health exists. Find Your Fire makes no real summers/submission/polling requests and cannot enable real analysis. It does not load the earlier provisional zones.json adapter as an authoritative dataset: geographic applicability is unavailable until the provider supplies a confirmed contract and geometry. Development mock processing stays explicit. The isolated provisional AnalysisClient is retained for tests/future agreement, not connected as production behavior.

## Export directory

From frontend/, set `$env:FIRE_DEMO_DIR = '../data/fires'` before `npm run dev`, `npm run data:demo` or `npm run build`. The existing server/build plugin serves or copies that directory under the same browser data URL. It requires index.json there. With no override or team exports, bundled offline fixtures remain available. No backend files are modified.

## Remaining backend gaps

No full nested result schema, implemented runner/model assembly, forecast method/interval contract, catalog/applicability exports, production API endpoints, or scientific meaning of confidence codes is available at this commit. Those gaps cannot be resolved using frontend fixtures as scientific authority.

Legacy development fixtures omit growth_forecast and comparison entirely; the frontend continues to accept these omissions as well as explicit null, although the backend writer requires both section keys. This is a documented compatibility exception, not evidence that the writer makes them optional.

For browser verification, `node scripts/contract-browser-fixtures.mjs` generates two explicitly labelled exports in a temporary directory: a complete existing example and a copy retaining only map.zone. Set FIRE_DEMO_DIR to the printed path and start Vite. Open `#/?view=fire&mode=examples&fire=contract_complete` and `#/?view=fire&mode=examples&fire=contract_omitted`. These are test-only copies, not scientific exports. Automated parser/loader checks pass; browser verification could not complete because the browser access host was unavailable and the native fallback window became minimized during interaction.
