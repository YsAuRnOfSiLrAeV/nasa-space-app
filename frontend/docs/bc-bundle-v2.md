# BC 2003: supplied bundle v2

The initial integration imported bc_2003_490 from the supplied frontend_katya/forestrecovery 0.14.0 export. Milestone 2 adds Quebec 1995, Quebec 2010 and Ontario 1988 through the same adapter; see [four-fire-examples.md](four-fire-examples.md). Each fire's eight resources are copied byte-for-byte. The root index is filtered to these four fires. Other fires and confidence-zone exports are not imported.

`src/data/bundleV2.ts` is the versioned adapter. The existing StudyDataApi uses the four v2 entries in place of the old BC documentation example and three development fixture cards. Legacy fixtures remain on disk and load in v1 configurations. Its bundleBaseUrl is configured only for bundled/example mode; FIRE_DEMO_DIR team exports retain their existing v1 behavior. Both formats use the same investigation components and persistent map.

The stage layer remains unavailable.                                                                                                        |

Unmapped fields remain in the unchanged source files: source x/y and CRS/rotation metadata (no reprojection is needed for supplied GeoJSON), model1 sample/pixel counts and share_gt_0_5, image pixel-size/processing notes, model2 interval_80 summary (the chart uses its supplied low/high series instead), manifest role descriptions. They are not turned into fabricated v1 summary metrics. No burn/reference masks are invented from perimeter membership. Legacy optical/model/lidar comparisons and stage proportions remain unavailable where not supplied by this bundle.

Optional bundles with no cells use null internal placeholders for existing component compatibility; no actual cell geometry is drawn and the UI says no cell grid was supplied. Optional image/GEDI/timeline absence remains absence. A cell record file without matching cell polygons is rejected rather than positioned approximately.

Verification covers actual BC source data, geometry identity and picking, PNG dimensions/rotation, measured GEDI placement, supplied forecast and bounds, timeline dimensions, optional files, malformed resources and shared-service loading. `npm run data:demo` validates v1 fixtures and the v2 bundle. Browser automation remains constrained by the unavailable browser host and native-window input/minimization failures; desktop/mobile visual sign-off is not claimed.

The importer now includes the complete supplied catalog; see [full-fire-catalog.md](full-fire-catalog.md). Reimport with `node scripts/import-fire-examples.mjs <supplied-frontend_katya-folder>`.
